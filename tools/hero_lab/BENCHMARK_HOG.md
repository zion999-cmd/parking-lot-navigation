
## Dataset

```
正样本   124（人工拖框，含车顶标记的整车）

```

## Training

```
分类器  cv2.ml.SVM_LINEAR, C=0.01
增强    仅正样本 ×4：旋转 ±15°、亮度 ±15%、对比 ±15%、轻高斯模糊、JPEG 45~90
        （不做改变几何结构的增强）
特征    1764 维，每窗口一次点积
```

## 对照验收线

| 验收线 | 实测 | 判定 |
|---|---|---|
| **≥ 20 FPS** | **209 FPS**（p95 5.4 ms） | ✅ 远超 |
| **recall ≥ 95%** | **98.4%**（124 中漏 2） | ✅ 通过 |
| **误检很少** | **0 / 496** | ✅ 通过 |

## 结论：**值得继续** ✅

HOG + Linear SVM 在这个任务上表现非常好，而且**快得离谱**（4.8 ms vs 现在 production 红掩码的 7~22 ms，
vs 模板匹配的 155 ms）。它还能**覆盖边缘**——红掩码在边缘也会掉，而 HOG 是整窗分类，不受"红色像素少"影响。

## 诚实边界（还不能下结论的部分）

1. **不是跨天验证**。三个批次是同一张桌子、同一套灯光、同一次布置。`recall 0.984` 证明的是
   「同一场景下的新位置、新朝向」，不是「换灯光/换桌子之后」。
2. **负样本是自动采的**，分布由采样网格决定，不是"难负样本"。真实场景里的困难样本
   （半个车、被挡住的车、车的影子）没有针对性覆盖。
3. **检测到的是 bbox，不是方向**。方向仍需在 bbox 内用几何方法（`red_arrow.py` 的 PCA 主轴 + 头尾）算。
4. **N=124 偏小**。按经验，这个数字上的 98% 置信区间大约 ±3%。

## 建议的下一步

1. **再采 2 个批次**：不同时段（灯全开/半开）+ 车贴边/被部分遮挡 → 看 recall 掉多少
2. 如果稳，就把 `live_detect.py` 的滑窗接到 bbox 输出，方向仍在 bbox 内用几何法算
3. 到这步再谈是否替换 production 的 `red_arrow.py`（**现在不动**）

## 追加：两步法（HOG 找车 + 框内箭头定向）

HOG 只回答"这个窗口是不是车"，方向仍由车顶的红箭头给出。两步都很便宜，而且互相验证：

```
① HOG + Linear SVM  →  车框 bbox            recall 0.984 / 4.8 ms
② 框内红箭头         →  朝向 heading         面积 + PCA 主轴 + 哪端更宽
③ 框内没有箭头       →  拒绝这个框           天然过滤假阳性
```

### 实测（`demo_live.py`，6 帧连续）

```
frame 0: box (672,272,96,96)  margin -0.06   arrow (725,310)  heading 93.8°
frame 1: box (672,272,96,96)  margin -0.12   arrow (725,309)  heading 94.6°
frame 2: box (288,128,64,64)  margin -0.04   arrow not found  -> 拒绝 ✓
frame 3: box (288,128,64,64)  margin -0.09   arrow not found  -> 拒绝 ✓
frame 4: box (672,272,96,96)  margin -0.06   arrow (725,309)  heading 95.6°
frame 5: box (672,272,96,96)  margin -0.05   arrow (725,309)  heading 94.4°
```

朝向稳定度 **±1°**（93.8 / 94.6 / 95.6 / 94.4）。

### 为什么第 ③ 步比调阈值可靠

真框的 margin 是 −0.06..−0.12，假框是 −0.04..−0.09 —— **两个区间重叠**，单靠 margin 分不开
✗。但**假框里没有红箭头** ✓，所以"框内必须能找到箭头"是一个**结构性**的判据，不是又一个阈值。

### 一个必须知道的细节

框内的**红箭头旋转 45° 后，外接框接近正方形**（实测 26×28，长宽比 1.08），会被
`red_arrow` 的 `MIN_ASPECT=1.2` **误杀** ✗。所以新增了 `red_arrow.detect_in_box()`：
只筛面积、不筛长宽比 —— 旋转本来就该由 PCA 处理，而不是由外接框的比例处理。

## 仍然没证明的

- **跨天/跨灯光**：三个批次是同一场景同一次布置
- **难负样本仍只覆盖"网格+模型自己的误检"**，没有系统性覆盖"半个车/被遮挡/车的影子"
- **124 个正样本**：98% 的置信区间约 ±3%
