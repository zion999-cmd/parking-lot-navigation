## 2. 本轮修复

### 2.1 P0

**P0-1 停止 HTTP 服务时的 use-after-free（CRITICAL）**
`stream_server_stop()` 直接 `httpd_stop()`，而每个客户端的 `mjpeg_stream` 任务仍持有
async request，随后调用 `httpd_resp_send_chunk()` / `httpd_req_async_handler_complete()`。
对照 ESP-IDF 源码，`httpd_stop()` → `httpd_delete()` 会 `free(hd)`，complete 又会解引用
`r->handle` 和已关闭的 socket。触发路径：串口 `clearwifi`，或旧凭据连接超时回落配网时，
恰有人正在看 `/stream`。

修复（`stream.c`）：
- 新增 `s_stopping` 与 `s_clients_mux`；
- handler 在临界区内完成「拒绝/计数」，停止后新请求返回 503；
- 流任务循环检查 `s_stopping`，退出时在临界区内减计数；
- `stream_server_stop()` 先置停止标志，等待 `s_clients == 0`（最多 10 s，
  大于 `send_wait_timeout` 3 s）再 `httpd_stop()`；超时会打印明确错误。

**P0-2 `vehicle.py` 使用 `sys` 但未导入（HIGH）**
箭头模板缺失时本应打印「hero detection is off」并降级，实际抛 `NameError` 终止主循环。
已补 `import sys`（`vision/src/vehicle.py`）。

**P0-3 干净 clone 无法编译固件（HIGH）**
`camera_diag.c` include 私有 `cam_hal.h` 并使用补丁新增的 `CAM_DIAG_COUNT`，
而 `patches/` 未入库、`managed_components/` 被忽略。
修复：
- `main/CMakeLists.txt` 在配置阶段检测组件是否已打补丁，未打则运行
  `patches/apply.py`；失败只告警；
- `camera_diag.c` 在未打补丁时提供零值 fallback，构建不再依赖补丁；
- `patches/apply.py`、`camera-diagnostics.patch` 已 `git add`（未提交）；
- 顺带修正诊断名数组比 `CAM_DIAG_COUNT` 少一项、循环把 NULL 交给 cJSON 的问题。

### 2.2 P1 — 固件稳健性与安全

## 3. 仍然存在的问题

### HIGH

1. **OTA 无真实性**：manifest 与固件同源但无签名，局域网攻击者可自建 manifest 并给
   SHA256。项目已在 `README.md` §9.5 接受该取舍；若沙盘离开可信网络，应升级为签名 manifest。
2. **`/api/bench` 无鉴权且在唯一 httpd 任务里阻塞约 20 s**（`stream.c`）。
   已补进架构文档，但它仍是低门槛 DoS 面，且与产品功能无关。建议移到诊断构建或限制调用。
3. **`serve.py` / `label_server.py` 绑定 `0.0.0.0` 后的暴露面**：`serve.py` 会把整个
   `vision/`（含 `src/`、`tests/`、`config/`）无鉴权地给局域网；`label_server` 接受无鉴权写。
   灯带依赖前者，项目文档已明说，属于沙盘信任模型的一部分，离开可信网络前必须收口。
4. **`tools/hero_lab/{eval_labels,diff_reference}.py` 无法运行**：它们 import 的
   `candidate_mask` 已在 `2fd132d` 随旧油漆管线删除。两个脚本是历史实验工具，
   建议删除或明确标注为归档；保留会让人以为可以复跑评估。

### MEDIUM

1. **对齐开启时的坐标系不一致**：检测用 warp 后的帧，主车在未 warp 的帧上定位，
   再拿参考系的车位/道路做 `location_of`。`--align off` 是默认值，故条件触发。
2. **`--zoom` 与参考帧没有绑定**：换 zoom 后旧 `reference.jpg` 与实时帧空间不一致，
   形状相同不会触发尺寸警告，表现为整场 OCCUPIED。另外 `zoom < 1` 的裁剪索引为负，
   实际取右下象限；CLI 不校验 `> 0`。
3. **只给 `--raw-port` 时永不推帧**：`raw_view.publish()` 被嵌在 `if live is not None`
   内，`finally` 也只在 `live` 存在时停止它。
4. **`[` / `]` 重新读取 reference**：`cv2.imread` 可能返回 None 后直接
   `set_reference(None, ...)`；且重新采参考后不重建 `detector_ref_frame` / `aligner`。
5. **分辨率变化会以未捕获 `RuntimeError` 退出**：`occupancy.py` 明确 raise，main 只打印
   warning 后继续调用。
6. **配置解析与校验**：`spot_config.load_spots` 的 `json.load` / `float()` 抛原生异常，
   调用方只捕获 `SpotConfigError`；重复车位 id 不检查。`emit_map` 前不
   `RoadNetwork.validate()`，悬空边会写出 JSON `Infinity`。
7. **编辑器**：取消入口标记不置 `dirty`；`A` 对齐静默清空手绘 `detect_polygon`；
   `_save_all` 忽略 `save()` 返回值仍报成功。
8. **道闸**：进入 CLOSING 后不再看触点开关，「防夹」只覆盖已抬起后仍有人；
   若这是需求，应写进文档。
9. **OTA 回滚确认缺口**：有旧凭据、60 s 连接超时后进入配网时，不会再次
   `ota_mark_current_valid()`；新镜像可能在下次复位时被回滚。建议在进入 PROVISIONING
   的状态迁移里统一确认。
10. **测试与 CI**：312 个 pytest 质量高（真实 HTTP、从发布页抽 JS 运行、回归测试），
    但 `start.sh`、`label_server`、`beacon`、OTA server、`publish.sh`、`hero_lab` 无测试；
    没有 CI、pytest 配置或覆盖率门槛。
11. **文档仍有漂移**：`README.md` §16 的目录树缺 `vision/src` 大部分模块、`web/`、
    `start.sh`、`tools/hero_lab`；`vision/README.md` 的个别历史实测段落仍按旧场景叙述。

### LOW

- `main.py` 差分叠加用 uint16 相加后转 uint8 会回绕，红色热点不会饱和。
- `write_state` 写失败仍返回 `(now, key)`，要等下一心跳重试。
