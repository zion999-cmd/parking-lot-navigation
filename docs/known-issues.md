## 1. hero 丢失后仍需按流程重启（**未解决**）

**现象**：hero 认错之后，除了重启 `main.py`（或 `./start.sh restart`）没有可靠的自愈手段。

**已经做过的**（`3c95867`）：`HeroBelief` 的外观 profile 学会 25 次后锁定，
只接受 ≥0.75 置信度的证据继续学。长跑实例实测 `profile_updates 9830` + `locked`，
它认的是几个小时前学到的外观，所以换车/换光就认错；新进程 profile 为空，用当前场景重学，因此"重启就好"。
现在 `takeover`（跟踪器持久跳到新位置）会调 `reset_profile()`，只丢外观、保留位置与状态。

**为什么还不够**：`takeover` 只覆盖"profile 被别的物体抓走"这一类。
其它错误（认到的东西一直稳定停留、永不触发 takeover）依然只能重启。

**要真正自愈，需要先有数据**：出错时把 `parking_state.json` 里的
`vehicle.profile_updates` / `vehicle.profile_locked` / `vehicle.confidence` / `hero_state`
四个值记下来，才能定义一个**有测量依据**的"错"判据。**目前没有这种判据，不猜。**

## 2. 识别层的数据抖动（**未解决，页面只能掩盖**）

**现象**：纸车在阈值边缘时，`parking_state.json` 的 `vehicle.visible` 每秒翻几次。
实测 20 秒 79 次采样里 **18 次翻转**。

**页面侧的缓解**（已做）：
- 图标透明**缓动**（每帧 1/4，约 66 ms 到位），不是硬切；
- `CAR_LOST_POLLS = 2`，单次丢失不算丢失；
- 相机跟随 `car.visible`（显示位姿），不跟实时 flag；
- 状态文字**不表现**丢失（丢失只在图标上），约定见 `navigation.html` 里 `routeSituation` 的注释。

**根治要改识别**：例如"连续 N 帧才切换 visible"或改阈值。
属于 `vision` 侧的算法改动，**需要授权，且要用 `tools/bench/hero_dynamic.py` 做前后对比**。
没有授权就不动。

## 3. 纸车作为 hero 的置信度与"垃圾"重叠（**未解决**）

而垃圾候选的置信度区间是 **0.25–0.49**。**没有任何阈值能把两者分开。**

两条出路，都需要用户决定：
1. 换更强的标记（饱和/不透明的红、面积更大）；

## 8. 约定（本轮确认的，写进代码注释）

- **丢失定位只表现在图标上**（半透明 ✓），**不进交互层**（状态文字、相机都不动）。
- **导航中车头朝上**，用**显示位姿** `car.h` 驱动；**只有结束导航**才回正北。
- **图标必须落在蓝色导航线上**，不是"看起来差不多"的车道线。
- **参考图检查只是诊断**，永远不替代车位状态（不因为遮挡就把车位全变黑）。
