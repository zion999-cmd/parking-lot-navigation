四个磁力计经一个 I2C 多路开关挂在 ESP32-S3 上，用于直接感知车位上的金属车辆。

## 1. 硬件连接

### ESP32-S3 侧

| ESP32-S3 | 接到 TCA9548A | 说明 |
|---|---|---|
| **GPIO41** | SDA | I2C 控制器 **0** |
| **GPIO42** | SCL | 100 kHz |
| **5V 或 3V3** | VIN | **看模块有没有 LDO**，见下 |
| **GND** | GND | 必须共地 |


#### ⚠️ VIN 接几伏取决于模块型号（2026-11-21 实测修正）

早期写的是"VIN 必须 3.3V，绝不能接 5V"。**那条假设是错的** ✗ —— 它假定模块上没有稳压器、
VIN 直接就是传感器电源。实际买到的 TCA9548A 模块大多带 LDO，VIN 是稳压器**输入**。

| 模块 | VIN | 传感器 VCC 从哪取 | 证据 |
|---|---|---|---|
| **带 LDO**（有 `3V3` 输出针）| **5V** ✓ | 模块的 `3V3` 输出针 ✓ | 接 3.3V 时 LDO 掉压 → 4 路**全部**消失；接 5V → 4 路 `err=0` ✓ |
| 无 LDO | **3.3V** ✓ | 同一根 3V3 ✓ | |

**不变的铁律**：`QMC5883P` 的 VDD 上限是 **3.6 V** ✗ —— 无论哪种模块，**传感器 VCC 必须是 3.3V**。
带 LDO 的模块就取它的 `3V3` 针；**绝不要把 5V 直接接到传感器 VCC** ✗。

**怎么判断**：看模块丝印有没有 `3V3` / `3.3V` 输出针。也可以看症状 ——
**VIN 接 3.3V 时全部无响应、接 5V 时正常 ⇒ 就是带 LDO 的板子** ✓（不需要万用表）。

---


### TCA9548A 侧

| TCA9548A | 接到 | 说明 |
|---|---|---|
| **A0 / A1 / A2** | GND / GND / GND | → 地址 **0x70**（实测确认） |
| **RST** | 3V3 | 低电平复位，接高保持工作 |
| **SD0 / SC0** | 传感器 1 的 SDA / SCL | |
| **SD1 / SC1** | 传感器 2 | |
| **SD2 / SC2** | 传感器 3 | |
| **SD3 / SC3** | **本机实测损坏** ✗ | 换任何传感器都不应答；第 4 颗改用 **SD4/SC4** ✓ |
| SD4–SD7 / SC4–SC7 | 不接 | |

### 传感器侧（关键，最容易接错的一条）

```
4 颗传感器的 VCC  →  全部并到 3.3V（带 LDO 的模块取它的 3V3 针）     ← mux 只切换 SDA/SCL，不传电
4 颗传感器的 GND  →  全部并到 GND
SDA → SDn，SCL → SCn（n = 0..3）
```

### 为什么必须要 mux

**QMC5883P 的 I2C 地址固定为 0x2C**，四颗直接挂同一条总线会地址冲突。TCA9548A 同一时刻只连通一个通道，所以每颗都保持 0x2C，只有被选中的那一颗在总线上。

### 为什么用 I2C 控制器 0（不是 1）

`camera.c` 里写的是 `config.sccb_i2c_port = 0`，但**这个值在本 build 里不生效** —— esp32-camera 按 `CONFIG_SCCB_HARDWARE_I2C_PORT1=y` 把相机 SCCB 装到了 **控制器 1**。

**实测证据**：磁力计一开始占用控制器 1，结果**相机初始化失败，板子无限重启**。改用控制器 0 后相机正常。

### 芯片识别

三款芯片都支持，**自动识别**，不靠猜：

| 芯片 | 地址 | 识别方式 | 量程/灵敏度 |
|---|---|---|---|
| HMC5883L | 0x1E | 0x0A 起 3 字节 == "H43" | 1090 LSB/G |
| QMC5883L | 0x0D | 0x0D == 0xFF | 3000 LSB/G |
| **QMC5883P** | **0x2C** | 0x00 == 0x80 | 2/8/12/30 G → 15000/3750/2500/1000 LSB/G |

**本项目用的是 QMC5883P**（LGA-16 贴片）。

### QMC5883P 的配置（实测出来的）

```
写 0x0B = 0x80     软复位
写 0x29 = 0x00     轴符号，不反转
写 0x0B = 0x0C     CONTROL2：量程 + set/reset 周期
写 0x0A = 0x3D     CONTROL1：测量模式 + 速率 + 过采样
等 220 ms
读 0x01..0x06      X/Y/Z 各 LSB,MSB
```

⚠️ **CONTROL1 是 0x0A，CONTROL2 是 0x0B** —— 和直觉相反，也和 QMC5883L（CONTROL1=0x09）不同。

⚠️ **量程不靠猜**：`0x0C` 实际选中的档位没有可靠文档（2/8/12/30 G 四种，灵敏度差 15 倍）。固件在启动时读一次原始值，**用地磁场 25–65 µT 这个外部事实反推档位**，并把结论写进 `diag`（`range=30G (371 counts -> 37.1 uT)`）。

### HTTP 接口

```
GET /api/mag
```

```json
{
  "ok": true, "count": 4,
  "sensors": [
    {"ch":0,"chip":"qmc5883p","ok":true,"x":290,"y":254,"z":64,
     "field_ut":39.2,"ut_per_lsb":0.10000,"reads":56,"errors":0}
  ],
  "diag": "bus:0x70;mux0x70:probe=ESP_OK,write=ESP_OK;ch0:0x2c;…"
}
```

- `field_ut` = |B|，微特斯拉
- `ut_per_lsb` = 反推出的量程换算系数
- `reads` / `errors` = 累计成功/失败次数
- `diag` = 启动时的总线扫描结果（谁在哪个通道应答），**排障时先看这个**

### 设计约束

- **best effort**：传感器不响应不影响相机、灯带、道闸；`mag_start()` 失败只记日志
- 启动时逐通道全地址扫描（0x08–0x77 × CH0–CH7），把结果放进 `diag`
- 只有固定配置读不到数时才跑三维扫描（CONTROL2 × CONTROL1 × 0x29，约 13 秒）

## 3. 调试时踩过的坑（都是实测教训）

| # | 坑 | 现象 | 原因 |
|---|---|---|---|
| 1 | 用 **legacy `driver/i2c`** | **板子无限重启** | 它的冲突检查直接 `abort()`。改用 `i2c_master`（新驱动），冲突只返回错误 |
| 2 | 占用 **I2C 控制器 1** | **相机初始化失败 → 无限重启** | SCCB 实际在控制器 1（见 §1） |
| 3 | 把 **TCA9548A 当有寄存器的器件** | 误报"没有 mux" | 它**没有寄存器**，写一个字节就是选通道；"写寄存器再读"必然 NACK |
| 4 | 只探 **0x1E / 0x0D** | 报"没有传感器" | 实际是 **0x2C** |
| 5 | **CONTROL1/CONTROL2 搞反** | 数据寄存器恒为 0 | 只写 0x0B，芯片根本没进测量模式 |
| 6 | **扫描停留 40 ms** | 正确配置也读成 0 | 转换速率可能只有 10 Hz（100 ms/次），读得太早 |
| 7 | **假设量程 2 G** | 报 2.5 µT（小 20 倍） | 实际是 30 G。**只有用地磁场做外部校验才发现** |
| 8 | **`snprintf` 返回值当长度** | `/api/mag` 返回空 / JSON 在 1023 字符处非法 | `snprintf` 返回"本应写入"的长度，超缓冲后 `httpd_resp_send(body, n)` 越界。用 `strlen(body)`，并把 body 加大 |
| 9 | 用 `str.replace` 改代码**没加断言** | "改动成功"但没生效 | 缩进不匹配会静默失败。改完必须 `grep` 验证 |

## 4. 测试方法

### 阶段 A：固件自检（面包板，30 秒）

```bash
curl -s http://<板子IP>/api/mag | python3 -m json.tool
```

**通过判据**

- [ ] `ok` = true，`count` = 4
- [ ] 每条的 `chip`（已知小问题：QMC5883P 会显示成 `QMC5883L`；数据是对的，只是名字映射没区分 P 型）
- [ ] `field_ut` 在 **25–65 µT**
- [ ] `reads` 每次读都增长，`errors` = 0
- [ ] 四路 `field_ut` 互相接近（同房间地磁场相同，通常差 < 15 µT）

**不通过时**：先看 `diag`

```
bus:0x70                                  → mux 在主总线上 ✓
mux0x70:probe=ESP_OK,write=ESP_OK         → mux 可读可写 ✓
ch0:0x2c  ch1:0x2c …                      → 每个通道上的器件 ✓
ch0:empty                                 → 该通道没有任何器件 ✗（接线/供电/上拉）
```

### 阶段 B：通道映射与串扰（面包板，5 分钟）

```bash
python tools/bench/mag_watch.py --host <板子IP>
```

**做法**：拿一块磁铁，**逐个**靠近 4 颗传感器（每次只靠近一颗，距离 2–3 cm）。

**通过判据**

- [ ] 磁铁靠近第 n 颗时，**只有 ch(n−1) 的 `d=` 大幅变化**，其余三路基本不动（|d| < 2 µT）
- [ ] 四颗都这样 → **mux 切换正确、通道映射正确**

**不通过时**：若四路一起变，说明 mux 没有真正切换（每条读的都是同一颗）。

### 阶段 C：噪声底（面包板或沙盘，60 秒）

```bash
python tools/bench/mag_watch.py --seconds 60      # 空场，没人靠近
```

**记录 `d=` 的抖动范围**，这就是噪声底 σ。

**参考判据**

| 空场抖动 | 判断 |
|---|---|
| \|d\| < 1 µT | 环境干净 |
| 1–3 µT | 可用 |
| 3–10 µT | 有干扰源（灯带 / 舵机 / 电源 / 附近铁器），需要定位 |
| > 10 µT | 基本不可用，先解决干扰 |

⚠️ **做这个测试时要把灯带点亮**（`LED_SELFTEST` 或正常状态），并在**舵机动作时**再测一次 —— 这两个是板上最大的干扰源。

### 阶段 D：单车响应幅度（装进沙盘后，关键）

**做法**：把车放到车位正中，再拿走，重复 5 次，记录 `d=` 的峰谷差。

**通过判据 —— 信噪比**

```
SNR = |车带来的 Δd| / 空场噪声 σ
```

| SNR | 结论 |
|---|---|
| ≥ 5 | 可用，简单阈值即可 |
| 3–5 | 可用，但需要时间滤波/迟滞 |
| < 3 | 不可靠，需要改安装（远离干扰、贴近车位中心）|

### 阶段 E：四路一致性（装进沙盘后）

- [ ] 同一台车分别放到 4 个被测车位，`Δd` 幅度应接近（差异 < 2 倍）
- [ ] 相邻车位空着时 `d` 不应明显变化（否则串扰，传感器间距或灵敏度问题）

### 阶段 F：与相机对照（装进沙盘后）

同一时刻比较：

```
相机判 OCCUPIED  ←→  地磁 d = ?
相机判 EMPTY     ←→  地磁 d = ?
```

目标是做一张混淆矩阵（后续的 `tools/bench/mag_bench.py`）。**这一步之前不要用「地磁占用」这个说法** —— 现在只有原始磁场，没有判别逻辑。

## 5. 已知限制

1. **绝对 |B| 不能当判据**：实测同一个传感器在几分钟内从 39 µT 变到 23 µT（挪动桌子/人靠近）。**必须用相对基线的变化**，且基线要定期重取。
2. **每颗传感器的基线不同**（实测 23 / 50 / 45 / 46 µT）—— 不能用一个全局阈值。
3. **磁力计怕铁**：传感器的安装位置要远离螺丝、铁架、舵机、音箱。
4. **WS2812 灯带的电流脉冲会产生磁场**：`LED_SELFTEST` 和正常点亮时都要复测噪声底。
5. **固件的已知小问题**：`/api/mag` 里 QMC5883P 的 `chip` 字段显示成 `QMC5883L`（数据正确、量程正确，只是名字映射没有区分 P 型）。

## 基线采集与可用性判定

四路的绝对 |B| 差异很大（实测 29–52 µT），所以**不能用统一阈值**，必须每路各采基线。
判定一个通道能不能用来判车位，看的不是磁场大小，而是**车造成的 Δ 相对空场噪声 σ 的倍数**：

```
SNR = |Δ| / σ        Δ = mean(有车) − mean(空场)        σ = 空场阶段的采样标准差
SNR ≥ 5  → 可以设单阈值判定（阈值取两点中点）
SNR < 5  → 两个分布重叠，阈值会在两侧都误报
```

工具：`tools/bench/mag_bench.py`（只依赖标准库）

```bash
# 引导式：3 轮 × 30 秒，阶段之间会停下来等你放车 / 拿车
tools/bench/mag_bench.py --host 192.168.3.118

# 快速看一次（每相 5 秒，不提示）
tools/bench/mag_bench.py --host 192.168.3.118 --seconds 5 --rounds 1 --yes

# 保留原始样本
tools/bench/mag_bench.py --host 192.168.3.118 --csv mag_bench.csv
```

输出包含每路的 `empty |B|` / `σ` / `car |B|` / `Δ` / `SNR`，以及 **每轴单独的 Δ 与 SNR** ——
车位金属通常主要改变某一个轴（实测 `dZ` 最灵敏），所以 |B| 不够时先看单轴。

退出码：全部通道达到 SNR 门槛返回 **0**，否则 **1**（可直接用于部署前把关）。

⚠️ 采集时的干扰前提：**灯带点亮、舵机动作**都要按实际工况开着，否则噪声底会被低估。

### ⚠️ 换线之后要重启板子，不要指望热重扫

试过两种运行时重扫（`GET /api/mag?rescan=1`），**两种都不可靠，已移除** ✗：

| 做法 | 实测结果 |
|---|---|
| 拆掉并重建 I2C 主总线 | 重建后**一个传感器都读不到**，直到重启 ✗ |
| 只重新探测通道（不碰总线）| **逐次退化**：4 个 → 2 个 → 1 个 → 0 个 ✗ |

结论：**发现只在开机时做** ✓（那条路径是验证过的 ✓）。改完线 → **断电重启或 OTA 一次** ✓。
`GET /api/mag` 的 `diag` 字段保留了开机扫描的完整记录 ✓，重启后一眼就能看出哪个通道没应答 ✓。

## P0005 — 地磁辅助占用（PC 侧最小闭环）

地磁**只做对照**：不修改视觉结果、不参与导航、不点灯带。全部在 PC 侧，固件不变。

### 1. 先测映射（不能假设 B1=CH0）

```bash
tools/bench/mag_map.py --host 192.168.3.118 --bays B1 B2 B3 B4 B5 B6 --seconds 6 --matrix
```

输出 `车位 × 通道` 的 |ΔB| 矩阵，一眼看出哪个通道在哪个车位下。然后显式写入：

```bash
tools/bench/mag_map.py --write-map B4=4 --bays B1 B2 B3 B4
```

映射存在 `vision/config/mag_bays.json`（**默认全 `null`** ✓）。未映射的车位 → `UNKNOWN`，**绝不会算成占用**。

⭐ 本机实测第一次跑就证明不能假设：`B4→ch4`（5.71 µT，13.9 倍余量）✓，但 `B1`/`B2` 都指向 `ch1`、`B3` 没有传感器响应 ✗。

### 2. 按 `r` 联合标定

在预览窗口按 `r`：视觉参考图照旧保存 ✓，同时**后台线程**采 3 秒地磁基线 ✓（不阻塞主循环 ✓）。
失败时**保留旧基线** ✗→✗ 不会覆盖 ✓。基线写入 `vision/data/mag_baseline.json`（gitignore ✓）。

### 3. 实时判定

```bash
python vision/src/main.py --source http://192.168.3.118/stream \
       --mag-map B4=4,B2=0,B1=1 --mag-log data/mag_compare.csv
```

```
mag  B1 vis=EMPTY mag=EMPTY 0.8uT   B2 vis=EMPTY mag=EMPTY 1.1uT   B4 vis=OCCUPIED mag=OCCUPIED 6.1uT
```

- 1 秒滑动平均 → ΔB = 三轴欧氏距离
- 阈值 **3.8 µT**、回差 **0.6 µT** ← **实测**：空场 60 秒 ΔB 的中位 1.22 / p95 2.29 / p99 3.44 µT（灯带在跑）
- `UNKNOWN` 条件：无基线 / 未映射 / 传感器 `ok=false` / 数据超过 2 秒 / `reads` 未更新
- `reads` 计数器不变**不算新样本**（HTTP 轮询率 ≠ 传感器采样率）
- 单位换算用**每颗传感器自己的** `ut_per_lsb`

### 4. 已知限制（实测，不是推测）

| 现象 | 数字 | 含义 |
|---|---|---|
| 空场 ΔB 漂移 | 中位 1.22 µT，p99 3.44 µT | 场在几十秒尺度上漂，不是白噪声 → 阈值必须 ≥3.8 µT |
| 车造成的 ΔB | **B4: 5.71 µT** ✓ / B2: 1.39 µT ✗ / B1: 0.50 µT ✗ | 只有 B4 明确可判 |
| 传感器数量 | 4 颗，但只有 1 颗确认在某车位正下方 | 其余 3 颗位置待测（见 §1 的矩阵） |

⚠️ 所以目前的结论是**部分可用**：`B4` 可判，`B1`/`B2`/`B3` 数据不足以支撑占用判定 —— 需要先把传感器挪到车位正下方，或换更强的响应安装方式。**实测未达到「四路都可判」。**
